# Северное графство — дизайн сайта

Продолжение [концепции](concept.md): здесь фиксируется структура сайта, поблочный состав страниц, дизайн-система и стек фронтенда.

Кликабельный макет: [`docs/mockups/prototype.html`](mockups/prototype.html) — открывается в браузере, без сборки.

## 1. Задачи сайта

Питомник — это не магазин. Человек выбирает щенка месяцами и решает не «где дешевле», а «кому я доверяю». Отсюда приоритеты:

1. **Доверие.** Показать производителей, титулы, тесты здоровья, условия содержания, лицо заводчика.
2. **Актуальность.** Ответить на главный вопрос «есть ли сейчас щенки» за первый экран.
3. **Простой контакт.** Заявка в 3 поля, а не анкета.
4. **Красота.** Фото — главный контент, интерфейс им не мешает.

Целевые действия: оставить заявку на щенка, написать в мессенджер, подписаться на соцсети.

## 2. Карта сайта

```
Главная
├── Наши собаки                    /dogs            фильтры: порода, пол, группа
│   └── Карточка собаки            /dogs/:slug      галерея, титулы, здоровье, родословная, потомство
├── Щенки                          /puppies         табы: доступны / ожидаются / выпускники
│   └── Карточка помёта            /litters/:slug   мать × отец, список щенков
├── О питомнике                    /about           история, заводчик, условия, дипломы, FAQ
├── Новости                        /news            лента
│   └── Новость                    /news/:slug
├── Статьи                         /articles        уход, воспитание, как выбрать щенка
│   └── Статья                     /articles/:slug
├── Контакты                       /contacts        форма заявки, мессенджеры, карта
└── Админка                        /admin           закрыта логином
```

**Что добавлено к первоначальному списку и зачем:**

| Раздел | Зачем нужен |
|--------|-------------|
| Карточка помёта | Покупатель выбирает не абстрактного щенка, а «щенка от этой пары». Пара родителей — половина решения. |
| Выпускники (таб в «Щенках») | Фото выросших собак в новых семьях — самое сильное социальное доказательство у питомников. |
| «Как купить щенка» (блок на `/puppies`) | Снимает 80% вопросов в переписке: этапы, документы, что входит в цену, доставка. |
| Статьи | SEO-трафик по запросам «кавалер кинг чарльз уход», «пудель характер» — люди приходят читать, остаются смотреть щенков. |
| FAQ (на `/about`) | То же самое, но про питомник: почему с документами, можно ли приехать, как с ветеринарией. |

Разделы «Новости» и «Статьи» держим раздельно в навигации (как в утверждённом макете шапки), но технически это одна сущность `Post` с полем `type` — экономит и бэкенд, и админку.

## 3. Структура страниц

### Главная

Порядок блоков — это воронка: зацепить → сориентировать → доказать → позвать.

1. **Герой** — фото на всю ширину, надзаголовок «Питомник кавалер кинг чарльз спаниелей и пуделей», H1, слоган, золотая кнопка «Познакомиться с нами».
2. **Три входа** — «Наши собаки» / «Щенки» / «О питомнике» карточками с фото. Дают выбрать маршрут сразу.
3. **Актуальные щенки** — 3–4 карточки с бейджем статуса и датой рождения. Если щенков нет — блок «Ожидаются помёты» с планами вязок, чтобы страница не выглядела пустой.
4. **Породы** — два крупных блока (кавалер и пудель): характер, размер, кому подходит, ссылка на отфильтрованный каталог.
5. **Наши собаки** — витрина 4 лучших производителей, ссылка на весь каталог.
6. **Полоса доверия** — 4 цифры на ледяном фоне: лет в разведении, выращено помётов, титулов, стран, куда уехали щенки.
7. **О питомнике коротко** — текст + фото заводчика, подпись от руки, ссылка на подробное.
8. **Новости** — 3 последние карточки.
9. **Отзывы** — 2–3 цитаты владельцев с фото собаки.
10. **CTA** — «Хотите щенка?» и короткая форма: имя, контакт, комментарий.
11. **Подвал** — логотип, контакты, соцсети, слоган, политика.

### Наши собаки (`/dogs`)

Шапка страницы (заголовок + подзаголовок на тёмном фоне) → строка фильтров (порода, пол, группа: производители / юниоры / ветераны) → сетка 3 колонки.

Карточка собаки в сетке: фото 4:5, кличка крупно, полное родословное имя мелким, строка «порода · пол · год рождения», бейдж титула, иконки пройденных тестов здоровья.

Фильтры живут в URL (`/dogs?breed=cavalier&sex=female`) — ссылку можно отправить в переписке, и TanStack Query кеширует каждый набор фильтров отдельно.

### Карточка собаки (`/dogs/:slug`)

- Галерея: крупное фото + миниатюры.
- Панель справа: полное имя, титулы, дата рождения, окрас, вес/рост, клеймо/чип, ссылка на родословную.
- **Здоровье** — таблица тестов со статусом (MVD, DNA, PRA, patella, дисплазия). Это то, что смотрят знающие покупатели.
- Описание характера.
- **Родословная** — 3 поколения простым деревом.
- **Потомство** — карточки помётов от этой собаки.

### Щенки (`/puppies`)

Табы: **Доступны** · **Ожидаются** · **Выпускники**.

Карточка помёта: буква помёта, «мать × отец» с миниатюрами и ссылками на их карточки, дата рождения и текущий возраст, порода, счётчик «свободно 2 из 5», строка щенков (фото, «мальчик №1», окрас, бейдж статуса, кнопка «Забронировать»).

Ниже — два постоянных блока: **«Как купить щенка»** (4 шага: заявка → знакомство → бронь → передача) и **«Что входит»** (метрика/родословная, чип, прививки, договор, стартовый корм, поддержка заводчика на всю жизнь).

Цену на сайте лучше не показывать числом — «по запросу» плюс форма. Это норма для породных питомников и снижает поток нецелевых обращений.

### О питомнике, Контакты

`/about`: история и фото усадьбы/дома → заводчик (фото, имя, стаж, пара слов от первого лица) → принципы разведения → условия содержания (галерея) → дипломы и сертификаты сеткой → FAQ аккордеоном.

`/contacts`: форма заявки (имя, телефон или телеграм, тема: щенок / вязка / консультация, сообщение, согласие на обработку) → мессенджеры крупными кнопками → город и «встреча по договорённости» → карта.

## 4. Дизайн-система

Палитра и шрифты — из [концепции](concept.md#палитра). Здесь — токены, которые лягут в Tailwind-тему.

### Токены

```
--navy:      #23364B   фон шапки/подвала, заголовки
--navy-deep: #1A2939   тёмные секции
--snow:      #F2F5F8   фон страницы
--gold:      #C9A227   акцент: кнопки, линии, гербы
--gold-soft: #E3C766   ховер, тонкие рамки
--ice:       #C7D6E2   фоновые блоки
--steel:     #8CA3B8   вторичный текст
--white:     #FFFFFF   карточки

радиусы:    10 / 16 / 999 (пилюля)
контейнер:  1200px, поля 24px
секция:     96px по вертикали (десктоп) / 56px (мобильный)
сетка:      12 колонок, gap 24px
```

Шрифты: **Playfair Display** — заголовки (H1 в верхнем регистре, с разрядкой ~0.04em), **Inter** — текст и интерфейс. Никакого третьего шрифта.

### Компоненты UI-кита

`Button` (primary золотая / ghost с золотой рамкой / link со стрелкой), `Badge` (статус щенка, титул), `Card` (собака, помёт, новость), `Section` (заголовок + виньетка + контент), `Gallery`, `Tabs`, `FilterBar`, `Accordion`, `Field`, `Crest` (герб SVG), `Divider` (золотая линия с ромбом посередине).

### Фирменные детали, которые держат стиль

- Золотая волосяная линия (1px) как разделитель секций — с маленьким ромбом или снежинкой по центру.
- Уголковые виньетки у важных блоков (как рамка на грамоте) — только у одного-двух блоков на странице, иначе шумно.
- Тёмные секции чередуются со снежно-белыми: ритм «светлое — тёмное — светлое» не даёт странице стать однообразной.
- Ховер на карточке: лёгкий подъём фото (scale 1.03) и золотая рамка. Без теней-«ватрушек».

### Адаптив

Mobile-first, брейкпоинты 640 / 768 / 1024 / 1280. Сетки: 1 колонка → 2 → 3. Шапка на мобильном — логотип + бургер, меню выезжает на весь экран тёмной панелью. Фильтры на мобильном — горизонтальный скролл чипами.

### Доступность

Контраст текста не ниже 4.5:1 (золото на белом использовать только крупным или на тёмном), фокус-обводка золотая, у всех фото — осмысленный `alt` («Кавалер кинг чарльз спаниель Аврора, 2 года»), формы с `label`, кликабельная зона не меньше 44px.

## 5. Фронтенд

### Стек

| Что | Чем | Почему |
|-----|-----|--------|
| Сборка | Vite | Быстро, без магии |
| UI | React 19 + TypeScript | По требованию |
| Данные | TanStack Query v5 | Кеш, статусы загрузки, инвалидация — без Redux |
| Роутинг | TanStack Router | Типизированные маршруты и search-параметры (важно для фильтров каталога) |
| Стили | Обычный CSS с переменными | Токены в одном файле, ноль зависимостей и сборочной магии; классы переносятся из макета один в один |
| Формы | react-hook-form + zod | Валидация заявки, общие схемы с типами API |
| Моки | MSW | Фронт разрабатывается до готовности Go-эндпоинтов |

Насчёт SEO: SPA на Vite индексируется хуже, чем SSR. Для питомника поисковый трафик важен, поэтому статичные страницы (главная, о питомнике, статьи) на этапе деплоя пререндерим (`vite-plugin-ssg` или предрендер через headless-браузер). Если органика станет основным каналом — переезд на Next.js остаётся открытым вариантом, структура компонентов это переживёт.

### Структура папок

```
frontend/
├── index.html
├── vite.config.ts
└── src/
    ├── app/                 провайдеры, роутер, layout (Header, Footer)
    ├── pages/               по странице на файл, только композиция
    ├── features/
    │   ├── dogs/            api.ts, queries.ts, DogCard, DogFilters, Pedigree
    │   ├── litters/
    │   ├── posts/
    │   └── requests/        форма заявки
    └── shared/
        ├── api/             http-клиент, queryKeys, zod-схемы
        ├── ui/              кнопки, карточки, бейджи, секции
        └── lib/             форматирование дат, возраст собаки
```

Правило: `pages/` ничего не знает про `fetch` — только собирает блоки. Запросы живут в `features/*/queries.ts` хуками вида `useDogs(filters)`.

### API-контракт (что нужно от бэкенда)

```
GET  /api/dogs?breed=&sex=&group=&page=      список собак
GET  /api/dogs/{slug}                        собака + родословная + потомство
GET  /api/litters?status=                    помёты (available|expected|past)
GET  /api/litters/{slug}                     помёт + щенки
GET  /api/posts?type=news|article&page=      лента
GET  /api/posts/{slug}                       публикация
POST /api/requests                           заявка
GET  /api/health
```

Ответы списков — конверт `{ "items": [...], "total": 0, "page": 1 }`, чтобы пагинация не ломала контракт. Даты — ISO 8601. Изображения — объект `{ "url", "width", "height", "alt" }`, чтобы фронт мог зарезервировать место и не «прыгать» при загрузке.

Бэкенду понадобится CORS для `http://localhost:5173` на время разработки.

## 6. Что дальше

1. Согласовать макет (`prototype.html`) и правки по блокам.
2. Поднять `frontend/` на Vite + React + TS, перенести токены в Tailwind-тему.
3. Собрать UI-кит и layout, затем страницы на моках (MSW).
4. Параллельно на бэкенде: PostgreSQL, модели, эндпоинты по контракту выше.
5. Связка, пререндер, деплой.
