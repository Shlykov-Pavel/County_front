# Как устроен проект

Два независимых приложения в одном репозитории: React-фронтенд и Go-бэкенд. Общаются
по HTTP через префикс `/api`.

```
Браузер
   │
   │  GET /                     статика: HTML, JS, CSS, фото
   │  GET /api/dogs             данные
   ▼
Фронтенд (React + Vite)
   │  в разработке: dev-сервер Vite на :5173 проксирует /api → :8080
   │  в проде:      статика и API живут за одним доменом
   ▼
Бэкенд (Go, net/http) :8080
   │
   ▼
PostgreSQL (планируется)
```

Единый префикс `/api` и общий домен выбраны сознательно: браузер видит один источник,
поэтому не нужны ни CORS, ни настройка адреса API в сборке фронта.

## Фронтенд — коротко

Vite + React 19 + TypeScript, данные на TanStack Query, стили — CSS с переменными.
Реализована главная страница; данные пока берутся из моков, потому что эндпоинтов ещё нет.

Поток данных: секция страницы → хук (`useDogs`, `usePuppies`, `usePosts`) → TanStack Query →
реализация `Api` (моки или `fetch`). Подробности, структура папок и инструкции —
в [frontend/README.md](../frontend/README.md).

## Бэкенд — что есть сейчас

Модуль `github.com/northcounty/backend`, Go 1.22, **ноль внешних зависимостей**: только
стандартная библиотека.

```
backend/
├── internal/
│   ├── config/config.go        настройки из переменных окружения
│   └── httpapi/
│       ├── router.go           регистрация маршрутов
│       ├── middleware.go       логирование запросов
│       └── health.go           GET /api/health + writeJSON
├── go.mod
└── Makefile
```

### Как обрабатывается запрос

1. `config.Load()` собирает настройки: `PORT` (по умолчанию 8080), `APP_ENV` и таймауты
   HTTP-сервера. Значения по умолчанию подобраны так, чтобы локальный запуск работал
   без настройки вообще.
2. `httpapi.New(logger)` создаёт структуру `API` — это место, куда позже добавятся
   зависимости: хранилище, сервисы.
3. `API.Routes()` создаёт `http.ServeMux` и регистрирует маршруты. Используется роутер
   из Go 1.22+, который понимает метод прямо в шаблоне:

```25:25:backend/internal/httpapi/router.go
	mux.HandleFunc("GET /api/health", a.handleHealth)
```

4. Весь mux оборачивается в `withLogging` — middleware пишет метод, путь, код ответа
   и длительность через `log/slog`. Код ответа перехватывается обёрткой `statusRecorder`
   над `http.ResponseWriter`, потому что стандартный интерфейс его не возвращает.
5. Обработчик `handleHealth` отдаёт `{"status":"ok","time":"..."}` через общую функцию
   `writeJSON`, которая ставит заголовок и сериализует любой ответ.

### Чего ещё нет

| Чего нет | Последствие |
|----------|-------------|
| `cmd/server/main.go` | **Сервер нельзя запустить.** `Makefile` и README ссылаются на `./cmd/server`, но пакета в репозитории нет: `make run` упадёт. |
| Эндпоинты домена | Реализован только `/api/health`, поэтому фронт работает на моках. |
| PostgreSQL и миграции | Данные негде хранить. |
| Авторизация и админка | Контент нечем наполнять. |
| CORS | Пока не нужен: dev-сервер Vite проксирует `/api` на `:8080`. Понадобится, только если фронт и API разъедутся по разным доменам. |

Дополнительно: на машине разработки сейчас не установлен Go (`go version` не находит команду),
так что перед запуском бэкенда понадобится `sudo apt install golang-go` или `snap install go`.

### Ближайшие шаги по бэкенду

1. Добавить `cmd/server/main.go`: чтение конфигурации, `http.Server` с таймаутами
   из `config.Config`, graceful shutdown по сигналу.
2. Подключить PostgreSQL и миграции.
3. Реализовать эндпоинты под контракт из [design.md](design.md#api-контракт-что-нужно-от-бэкенда):
   `/api/dogs`, `/api/litters`, `/api/puppies`, `/api/posts`, `POST /api/requests`.
4. После этого на фронте достаточно поставить `VITE_USE_MOCKS=false`.
