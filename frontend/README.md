# Фронтенд — Северное графство

React 19 + TypeScript на Vite. Данные — TanStack Query. Стили — обычный CSS с переменными,
без препроцессоров и UI-библиотек.

Сейчас реализована одна страница — главная. Разметка повторяет утверждённый макет
[`docs/mockups/prototype.html`](../docs/mockups/prototype.html).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

Другие команды: `npm run build` (проверка типов + сборка в `dist/`), `npm run typecheck`,
`npm run preview` (посмотреть собранную версию).

## Структура

```
src/
├── main.tsx              точка входа: провайдер Query, подключение стилей
├── app/
│   ├── App.tsx           каркас: шапка, страница, подвал
│   └── queryClient.ts    настройки кеша по умолчанию
├── pages/
│   └── HomePage.tsx      только композиция секций, без запросов
├── components/
│   ├── layout/           Header, Footer
│   ├── home/             секции главной, каждая — отдельный файл
│   └── ui/               переиспользуемое: карточки, заголовок секции, Loadable, герб
├── api/
│   ├── types.ts          типы данных и интерфейс Api
│   ├── http.ts           настоящий клиент: fetch к /api/*
│   ├── mock.ts           моки на время, пока эндпоинтов нет
│   ├── index.ts          выбор реализации: моки или HTTP
│   └── queries.ts        ключи кеша и хуки useDogs / usePuppies / usePosts / useHealth
├── lib/labels.ts         перевод значений API в текст интерфейса, формат дат
└── styles/               tokens → base → ui → layout
```

Правило разделения: **страница не знает про сеть**. Она собирает секции; секция берёт данные
своим хуком; хук ходит в `api`. Поэтому подмена моков на реальный бэкенд не задевает компоненты.

## Как ходят данные

```
Секция → хук из api/queries.ts → TanStack Query → api (моки или fetch) → /api/... → Go
```

1. Секция вызывает хук, например `usePuppies({ status: "free", limit: 3 })`.
2. Хук отдаёт запрос в TanStack Query с ключом `["puppies", { status, limit }]`.
   Ключ определяет ячейку кеша: два разных набора параметров кешируются отдельно.
3. Query смотрит в кеш. Свежие данные (моложе минуты) отдаются сразу, без сети.
4. Компонент получает `isPending` / `isError` / `data`. Эти три состояния разбирает
   общий `Loadable`, чтобы секции не повторяли одинаковые проверки.

Настройки кеша заданы один раз в `app/queryClient.ts`: `staleTime` минута, без перезапроса
при возврате в вкладку, одна повторная попытка при ошибке. Контент питомника меняется редко,
дёргать сервер чаще смысла нет.

В режиме разработки внизу слева доступны Devtools TanStack Query — там видно все запросы,
их ключи, состояние кеша и данные.

## Моки и переключение на настоящий API

`api/index.ts` выбирает реализацию по переменной окружения:

```ts
const useMocks = import.meta.env.VITE_USE_MOCKS !== "false";
export const api: Api = useMocks ? mockApi : httpApi;
```

По умолчанию работают моки, потому что в Go пока есть только `/api/health`. Когда появятся
эндпоинты, создайте `frontend/.env.local` со строкой `VITE_USE_MOCKS=false` и поднимите
бэкенд на `localhost:8080` — Vite проксирует туда все запросы к `/api` (см. `vite.config.ts`),
поэтому в браузере остаётся один источник и CORS не нужен.

Обе реализации подчиняются интерфейсу `Api` из `api/types.ts`: если контракт разъедется,
это заметит TypeScript, а не пользователь.

## Как добавить секцию на главную

1. Создать `components/home/MySection.tsx`.
2. Данные, если нужны, брать хуком из `api/queries.ts` и оборачивать в `Loadable`.
3. Вставить секцию в `pages/HomePage.tsx` в нужном месте.

Классы вроде `section`, `container`, `card`, `badge` уже есть в `styles/ui.css` —
новые стили нужны, только если блок действительно уникальный.
